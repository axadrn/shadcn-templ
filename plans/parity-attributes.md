## Context

Every component carries private `data-tui-*` attributes: 278 distinct names in `components/*/*.templ`, 2611 uses across components, docs site and blocks. They date from templUI (`changelog/v0-84-0.md`) and do three different jobs at once:

- **Selectors** for the JS (`[data-tui-select-content]`, `[data-tui-select-item]`), next to the `data-slot` attribute shadcn already renders on the same element (241 `data-slot` uses in the templ files).
- **State** that Base UI renders under its own names (`data-tui-select-initial-open` where Base UI renders `data-open`).
- **Props** that Base UI keeps in React memory and never renders (`data-tui-popover-side-offset` for `sideOffset`, `data-tui-hovercard-delay` for `delay`).

On top of that sit a few invented concepts that exist in neither Base UI nor shadcn: `*-controlled` (Base UI says: `open` is set instead of `defaultOpen`), `select-initial-open-method` (Base UI internal state, never a prop), `dropdownmenu-mobile-side` and `-mobile-align`.

The earlier attempt on `feat/shadcn-base-ui-1to1-parity` (deleted 2026-09-23, was one WIP commit, 72 commits behind `main`) replaced selectors with `data-slot`, which was right, and moved props to unprefixed names like `data-open-method`, which invented Base UI attributes that do not exist. It also mixed the rename with new components and a component runtime. Nothing of it is reused.

The shared runtime is `window.tui` (`scroll_lock.js:414`, `dialog.js:752`, `drawer.js:1359`, `popover.js:373`, `resizable.js:1252`) and the per-element expandos are `_tui*` (`_tuiPortalOwner`, `_tuiOpen`, `_tuiOpenMethod`, ...). The bundle is `components/*/*.js` in lexical order (`update_scripts.go:22`), regenerated into `components/scripts_bundle.go` by the scripts watcher; `_templ.go` files by the templ watcher; `assets/css/output.css` by the tailwind watcher. None of the three is edited or generated by hand (`AGENTS.md`).

Readers of the attributes outside `components/`: `internal/ui/examples` (15 files), `internal/ui/modules` (7), `internal/ui/pages` (5), `internal/ui/charts` (4), `blocks/` (sidebar09, sidebar10, sidebar12, sidebar15, dashboard01), `assets/js` (2), `assets/css/globals.css` (`data-tui-code-line-numbers`, docs code block only), Go tests in 19 component and block packages, and two docs pages (`carousel.md`, `date-picker.md`). The docs site also has attributes that are not components at all: `data-tui-block-*`, `data-tui-chart-*`, `data-tui-code-*`, `data-tui-create-*`.

Test tooling: Playwright in `tmp/a11y-600/node_modules`, probes as `tmp/<topic>/*.mjs` (gitignored), dev server `task dev` on 8090, previews at `/preview/<name>` (390 examples), docs pages at `/docs/components/<name>`. `tmp/a11y-600/a11y.mjs` is the keyboard and ARIA scenario runner from `plans/a11y-600.md`; it works on `data-slot` and ARIA only and is the regression net here.

## Decisions

Three rules. They go into `AGENTS.md` in task 2 and are the whole design.

- **Rule 1: Go props are Base UI props.** A component's `Props` struct carries the Base UI props of the matching part under the same names in Go casing: `Open`, `DefaultOpen`, `Modal`, `SideOffset`, `CloseDelay`. Only value props; callbacks, `render`, refs and anything that is a function have no server-rendered form and are not ported. Only props a component or example uses today; a prop is added the day it is needed, under its Base UI name. A prop that is not in the Base UI reference for that part does not exist. That removes `OpenMethod` (internal state, `select.templ:71`), `MobileSide`, `MobileAlign`, and the `*Controlled` notion: controlled means the `Open` or `Value` pointer is set, uncontrolled means `DefaultOpen` or `DefaultValue` is used, exactly as Base UI reads `open` versus `defaultOpen`.
- **Rule 2: the DOM is shadcn.** Every element renders `data-slot` as shadcn does, the state attributes Base UI renders (`data-open`, `data-closed`, `data-checked`, `data-disabled`, `data-side`, `data-align`, `data-orientation`, `data-starting-style`, `data-ending-style`, ...), and role and ARIA as Base UI. The JS selects by `data-slot` and reads state from those attributes. No other selector attribute exists. An unprefixed `data-*` is allowed only when the upstream part renders it; this covers today's unprefixed inventions too (`data-copy-button`, `data-target-id`, `data-panel-open`, `data-activate-on-focus`, ...), which fall under rule 3 or are deleted.
- **Rule 3: a prop Base UI does not render is `data-templ-<prop>`.** Kebab-case of the Base UI prop name, on the element the Base UI part receives it: `data-templ-side-offset`, `data-templ-close-delay`, `data-templ-snap-points`, `data-templ-open` (present means controlled). The name after the prefix is checkable by grep against the Base UI reference; a name that is not a prop there is not allowed. Where our port needs a marker Base UI has no DOM for because React holds it in memory (the portal `<template>`, the owner link of a moved popup, the tabs id link), it is `data-templ-<name>` and the Executor log names the Base UI code it stands in for.

Consequences, so nobody has to derive them:

- **Prefix everywhere else is `templ`.** `window.tui` becomes `window.templ`, `_tui*` expandos become `_templ*`, `tuiDrawerInitialized` and friends follow. Same word in DOM, JS and prose, nothing left that says templUI.
- **The scroll lock attribute is Base UI's.** `data-tui-scroll-locked` on `<html>` becomes `data-base-ui-scroll-locked`, the literal name `useScrollLock.ts` sets, because that is what a shadcn page shows (`plans/scroll-lock.md`).
- **Docs-site-only attributes get the mechanical rename.** `data-tui-block-*`, `data-tui-chart-*`, `data-tui-code-*`, `data-tui-create-*` and the other docs module attributes are not shadcn components; they are renamed to `data-templ-*` one to one, no other change, in one task at the end.
- **One component per task, same procedure every time.** For the component's directory: read the Base UI reference for each part (source copies in `tmp/parity-attributes/baseui/`, shadcn's `ui/*.tsx` in `tmp/parity-attributes/shadcn/`), classify every `data-*` on every element as slot, upstream state, prop, or invention; rewrite templ, JS, Go tests and every reader in the repo (`internal/ui`, `blocks`, `assets/js`) in the same commit; record the mapping table in the Executor log (old name, new name or "deleted", Base UI source). No behavior change, no class change, no markup change beyond attributes; the watcher-generated files are committed with the task.
- **The proof is a DOM diff plus the scenario runner.** `tmp/parity-attributes/dom.mjs` dumps, for a list of pages, every element's tag, `data-slot` and sorted attribute names (values dropped) after the page loads and again after one open interaction per page; the diff between the `main` baseline and the task's run must show only renamed or deleted attributes, never a changed tag, slot, role or ARIA attribute. `tmp/a11y-600/a11y.mjs` must pass unchanged in both engines after every task.
- **Order follows the bundle's dependencies.** Shared runtime first, leaf components, then anchored popups, then the dialog family, then composites that embed them, then docs-site-only, then the migration note.
- **This is a breaking change, said once.** A changelog entry in the next release file states the rule and the two grep commands that find a user's own `data-tui-*` readers. No compatibility layer, no dual attributes.
- **Nothing else changes.** No new components, no new props beyond the ones that replace an invention, no runtime, no lifecycle refactor. Those are later plans on later branches.
